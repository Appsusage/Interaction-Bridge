# Mandatory ChatGPT Web Session Rules for the AI Agent

When the agent needs to talk to ChatGPT through the web browser, follow this procedure automatically. The user must not need to explain it again.

1. ALWAYS check and reuse the last known Playwright session first. Start with `POST http://127.0.0.1:3000/browser/read` using the saved `sessionId`, `Content-Type: application/json`, and `x-browser-key: $BROWSER_API_KEY`.
2. Never create a new session or restart login just because one selector/action failed. Do not call `/browser/session` unless existing-session recovery has been checked and is demonstrably impossible.
3. A browser session ID, persistent Chromium profile, ChatGPT conversation URL/ID, and agent task ID are different things; store them separately.
4. On the successful test session, ID was `1792241456256-v95pmtm84w` and conversation URL was `https://chatgpt.com/c/6ad37538-30e4-83ec-8aab-d49150f1e753`. These are historical identifiers; first check if the session still exists before using them.
5. The observed composer selector was `[aria-label='Ask ChatGPT']`. Generic `[contenteditable='true']` matched two elements (the Python code editor and ChatGPT composer), so avoid it. The observed send selector was `button[aria-label*=Send]`. Inspect the current DOM and uniqueness before acting because the website can change.
6. Persist a task record before sending: task ID, prompt hash, session ID, conversation URL, and state. After clicking Send, mark the task as sent. If interrupted or timed out, read the current page and task state before retrying; never blindly resend.
7. Poll `/browser/read` until the exact new user message and the corresponding real assistant answer are visible and generation is complete. Only then mark the task completed. A successful click or HTTP 200 is not proof of a completed answer.
8. If the session ID has vanished, inspect/recover the existing persistent Chromium context/profile before opening a new session. Do not assume a missing in-memory session means login cookies are lost.
9. If login, CAPTCHA, or a security check appears, stop automation and wait for the user to complete normal verification. Never bypass security checks.
10. Save the answer and outcome in the task result. Report `COMPLETED`, `WAITING`, or `FAILED` truthfully; do not claim success without reading the actual answer.

Verified interaction: S772/S777 read real ChatGPT responses in the same session; S779 typed the third question using the specific composer selector; S780 clicked Send; S786 confirmed the same conversation and the third real answer, ending with `Response complete`.
