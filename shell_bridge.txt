# ChatGPT Web Interaction Playbook (Critical)

This is an operating rule for the AI Agent. Follow it automatically; do not ask the user to repeat it.

## Non-negotiable rule
Reuse the existing Playwright browser session and logged-in ChatGPT page first. Never create a new browser session or restart login just because a selector/action failed. Do not call `/browser/session` until the existing session has been checked and recovery is confirmed impossible.

## Proven working session
- Session ID at the successful test: `1792241456256-v95pmtm84w`.
- ChatGPT conversation URL observed: `https://chatgpt.com/c/6ad37538-30e4-83ec-8aab-d49150f1e753`.
- Existing-session check: `POST /browser/read` with `{"sessionId":"<saved-session-id>"}`.
- Composer selector observed on current ChatGPT UI: `[aria-label='Ask ChatGPT']`. Do not use generic `[contenteditable='true']`; it matched two elements.
- Send button selector that worked: `button[aria-label*=Send]`.
- Read actual page response using `/browser/read`; require the new user message and the assistant's response in page text before marking success.
- API base: `http://127.0.0.1:3000`. Include `Content-Type: application/json` and `x-browser-key: $BROWSER_API_KEY`.

## Required procedure
1. Load the last saved session ID and last conversation URL from persistent state.
2. Call `/browser/read` on the existing session first. If it works, keep using that session.
3. If read fails, inspect/recover the existing persistent Chromium context/profile before considering a new session. A session ID disappearing after backend restart does not prove the login profile is gone.
4. Check page text and URL. If logged in, continue in the current page/conversation. If login/CAPTCHA/security verification appears, stop automated login attempts and leave the page for the user; never bypass verification.
5. Before sending, inspect current DOM/accessibility labels and ensure the composer is uniquely identified. Use `[aria-label='Ask ChatGPT']` only when it exists uniquely; otherwise re-read the page and identify the current real composer.
6. Persist task ID, prompt hash, session ID, conversation URL, and state `PREPARED` before typing. After typing/sending, persist `SENT` and timestamp. If interrupted after sending, read the page before any retry to avoid duplicate messages.
7. Click send, then poll `/browser/read` at intervals. Confirm the exact new user question is visible and the assistant response is complete (e.g. completion indicator / no active generation). Persist the answer and mark `COMPLETED` only after reading the real assistant message.
8. On timeout, read state first; do not immediately resend. Return explicit `WAITING`, `FAILED`, or `COMPLETED` status rather than claiming success without evidence.
9. Do not create a new browser session unless existing-session recovery is demonstrably impossible. If one must be created, record why and check the persistent profile/login state before navigating.

## Verified test history
- S772: read ChatGPT conversation and the first real assistant response.
- S776/S777: read the second question's long response; page showed `Response complete`.
- S778: generic `[contenteditable='true']` failed strict mode because it matched the Python code editor and ChatGPT composer.
- S779: `[aria-label='Ask ChatGPT']` successfully typed the third question.
- S780: `button[aria-label*=Send]` successfully clicked.
- S781/S783: `/browser/read` confirmed the same conversation URL and read ChatGPT's real response to the third question; answer was still generating at last read, so poll again before treating it complete.

## Integration requirement
The agent's decision flow must invoke this playbook before any ChatGPT browser operation. Keep the persistent session registry/task journal in code, not only in chat history. Store the session ID and conversation URL separately from the persistent Chromium profile path. Do not persist passwords or verification codes.
EOF
