宠宝 Cursor / AI 鼠标功能说明
=============================

目标
----
让宠宝同时承担两种角色：
1. 保留原本的自主宠宝行为，例如自行移动、观察页面、避让内容、表情和互动。
2. 作为 AI 可优先控制的网页鼠标：AI 能指定目标位置、移动宠宝、指向元素，并执行点击等鼠标操作。

优先级
------
- AI 正在执行明确的鼠标任务时，AI 控制优先于宠宝自主移动。
- AI 任务结束、取消或超时后，释放控制权，恢复原有宠宝行为。
- 交接时应避免宠宝自主逻辑同时改写坐标，避免抖动、跳位或覆盖 AI 命令。
- 控制权状态应明确，例如 idle / ai-controlled / executing-click / returning-to-autonomy。

鼠标与页面交互的区别
--------------------
- 宠宝的可见位置/动画由宠宝 DOM 和 CSS 控制。
- 页面点击应针对真实目标元素执行标准网页交互，并尽可能使用浏览器原生 click / PointerEvent / MouseEvent 机制；需要注意，脚本派发的合成事件并不等同于真实硬件鼠标事件，有些浏览器安全敏感操作会拒绝合成事件。
- 如果用户要求的是操作网页内按钮、链接、输入框，优先通过 DOM 定位目标元素并检查可见性、是否被遮挡、是否可交互，再移动宠宝到目标并触发相应交互。
- 对于仅能通过真实系统指针操作的浏览器界面、浏览器外应用或安全敏感动作，网页内的宠宝 DOM 无法单独保证等同于物理鼠标；需要浏览器自动化/操作系统级指针能力，不能把模拟 DOM 点击描述为真实硬件点击。
- 点击之前应校验目标，避免误点、重复提交、购买、删除、发送等有外部影响的动作。涉及重要或不可逆操作时应先请求用户确认。

建议的模块边界
----------------
- cursor/：AI 鼠标控制逻辑与接口，负责控制权、目标解析、移动/点击任务和任务状态。
- pet.js：保留宠宝 DOM 与现有自主行为；后续仅在明确设计后添加控制接口，不要直接重写现有动作/视线逻辑。
- pet.css / limbo.css：先不改动。Cursor 的视觉反馈如需要独立样式，应放在 cursor 模块自己的 CSS 中，并先确认入口加载方式，避免与现有宠宝样式冲突。
- 页面交互执行层：负责查找目标、校验可见性/可点击状态、执行点击或输入，并返回成功/失败原因。
- AI 控制接口：接收结构化命令（如 move_to、point_at、click、release_control），校验参数后交给执行层。不能把任意未校验的自然语言直接当作点击坐标或操作命令。

建议命令概念
------------
- acquire_control：AI 获取宠宝控制权。
- move_to：将宠宝移动到目标坐标或元素。
- point_at：移动并指向某个元素，不点击。
- click：校验目标后点击。
- double_click / right_click：仅在确实需要并且目标支持时实现。
- release_control：结束 AI 控制，恢复自主行为。
- cancel：取消当前动作并安全释放控制权。

坐标与布局注意事项
------------------
- 统一使用 viewport CSS 像素坐标；不要混用屏幕物理像素、设备像素比（devicePixelRatio）和页面文档坐标。
- 点击目标元素时，优先使用元素当前可见矩形的中心点或明确指定的可点击子元素；考虑滚动、缩放、固定定位、iframe、遮挡和移动端触控布局。
- 宠宝动画终点应与目标坐标一致；点击前再次核验目标位置，防止页面重排后点错。
- 目标不在视口内时，先决定是否滚动到目标；滚动会影响原本的宠宝避让逻辑，需要明确控制权优先级。

实施约束
--------
- 先检查现有 pet.js 的自主移动入口、坐标系和点击/互动逻辑，再设计最小接入点。
- 不删除或合并 pet.css / limbo.css。
- 不修改已确认正确的眼睛视线镜像、脸部角度、嘴和脸颊定位规则。
- 不改动与宠宝鼠标功能无关的前端、登录、路由或其他模块。
- 新模块先独立实现并验证，再接入 pet.js；每一步记录变更与验证结果。
- 测试至少覆盖：AI 控制期间自主移动不会抢位置；点击普通按钮/链接/输入框；目标被遮挡/消失；页面滚动或重排；取消/超时后恢复自主行为；移动端视口。
- 点击/提交/删除/购买/发送等有副作用操作应设置确认或安全策略，避免重复执行。
