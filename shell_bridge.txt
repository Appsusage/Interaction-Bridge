#!/bin/sh
set -eu
cd /home/runner/workspace/ai-agent

TARGET="backend/extension/pet/recognition/RECOGNITION_SPEC.txt"
DIR="backend/extension/pet/recognition"

if [ -e "$TARGET" ]; then
  echo "ERROR: target already exists; refusing to overwrite: $TARGET"
  exit 17
fi

mkdir -p "$DIR"
cat > "$TARGET" <<'SPEC'
PET RECOGNITION / PERCEPTION MODULE — DESIGN SPECIFICATION
==========================================================

Purpose
-------
Create an independent module folder for the pet's visual recognition and
object/target discrimination capabilities. The pet should retain its existing
autonomous behavior while AI-directed actions can use perception to understand
what is visible and where a target is located.

Planned responsibilities
------------------------
1. Screen/frame perception:
   - Receive an explicitly available screenshot or browser viewport image.
   - Track image dimensions, viewport origin, scale, and capture timestamp.
   - Avoid mixing screenshot coordinates with page coordinates.

2. Visual target detection:
   - Identify visible UI controls and ordinary visual objects where feasible.
   - Return candidate labels, bounding boxes/points, confidence, and evidence.
   - Distinguish "not found", "ambiguous", "occluded", and "low confidence".
   - Never claim recognition succeeded without a result that can be checked.

3. Target-to-pointer mapping:
   - Convert a selected target point into the coordinate system used by the
     real pointer controller.
   - Re-check the target immediately before an action when the page may move,
     scroll, resize, animate, or reflow.
   - Keep recognition separate from cursor movement and clicking.

4. AI / pet coordination:
   - Support a perception result being used by the cursor module.
   - AI control may take priority over pet autonomy while a task is active.
   - On release/cancel/failure, return control safely to the existing pet logic.
   - Keep existing pet appearance, gaze, face geometry, and CSS behavior intact.

5. Verification and reporting:
   - After a permitted action, inspect the resulting screen/state where possible.
   - Report success only when the expected result is observed.
   - Otherwise report uncertainty or failure and stop unsafe retries.

Suggested future module boundaries
----------------------------------
recognition/
  RECOGNITION_SPEC.txt       This specification
  index.js                   Future public API / coordinator
  screen_capture.js          Future screenshot/frame input adapter
  detect_targets.js          Future visual target detector
  classify_objects.js        Future object/UI classification
  coordinate_mapper.js       Future image-to-pointer coordinate conversion
  verify_result.js           Future post-action visual verification
  tests/                     Future deterministic tests and sample fixtures

The above are planned names only. Do not create implementation files until the
existing browser, pet, and cursor architecture has been inspected.

Security and consent boundary
-----------------------------
- This module is for general visual understanding and permitted UI assistance.
- It must not solve, classify answers for, or automate clicks intended to pass
  CAPTCHA, Google reCAPTCHA, anti-bot challenges, or other security verification
  designed to distinguish a person from automation.
- If such a challenge appears, pause the automated task, notify the user, and
  allow the user to complete the verification themselves. Resume only after the
  user confirms it is complete.
- For sensitive or consequential actions (payments, purchases, deletion,
  sending messages, account/security changes), require explicit user approval
  before committing the action.
- Do not attempt to evade site restrictions or impersonate a physical user.
- Visual recognition is not itself proof that a click was delivered or accepted.

Integration constraints
-----------------------
- Keep recognition independent from cursor control.
- Do not modify pet.js, pet.css, limbo.css, gaze calculations, or face geometry
  merely to add this folder.
- Before implementation, inspect the current pet movement loop, browser
  screenshot/capture support, pointer-control mechanism, and command interface.
- Use the smallest possible integration point and test autonomous mode,
  AI-control priority, cancellation, and return-to-autonomy.
SPEC

echo "=== CREATED ==="
printf '%s\n' "$TARGET"
wc -l "$TARGET"
sha256sum "$TARGET"
echo "=== PET MODULE FOLDERS ==="
find backend/extension/pet -maxdepth 2 -type d -print | sort
