宠宝（Pet / Limbo）样式与眼睛位置维护指南
========================================

目的
----

涉及文件
--------
1. backend/extension/pet/limbo/pet.js
   行为和动态状态。负责创建宠宝 DOM、根据目标计算视线、设置 data-gaze 与 CSS 自定义属性、入场/成长/互动，以及滚动后检查遮挡并调整位置。
2. backend/extension/pet/limbo/pet.css
   一份包含完整宠宝外观的样式表，包含主体、脸、眼睛、嘴、脸颊、视线状态、新生/成长等规则。它不是单纯的“基础样式”。
3. backend/extension/pet/limbo/limbo.css

pet.js 控制什么
---------------
- setGaze()（当前代码约第 61–112 行）：设置宠宝的 data-gaze，并动态写入 CSS 变量。它决定当前视线状态以及部分眼框位置/宽度数值。
- spawnFrom()（当前代码约第 141–170 行）：创建 .limbo-pet DOM 结构，包括脸、眼睛、瞳孔、嘴、脸颊和文字气泡。
- 入场、动作、表情、互动和滚动后遮挡检查在 setGaze() 以外的代码中。
- pet.js 不会凭空决定最终像素样式；最终呈现还取决于实际加载的 CSS、选择器优先级、规则顺序以及是否有 !important。

眼睛位置：JS 动态变量
---------------------
setGaze() 当前的镜像计算如下。请勿随意改动；这是已确认外观正确的版本：

  orb.style.setProperty("--gaze-strength", String(strength));
  // Mirror the complete left-looking eye boxes across the 34px face.
  const nearWidth = Math.max(5, 8 - 3 * strength);
  const farWidth = Math.min(9, 8 + strength);
  const leftPoseLeftEyeX = Math.max(0, 3 - 10 * strength);
  const leftPoseRightEyeX = 23 - 9 * strength;
  const rightPoseLeftEyeX = 34 - (leftPoseRightEyeX + farWidth);
  const rightPoseRightEyeX = 34 - (leftPoseLeftEyeX + nearWidth);
  orb.style.setProperty("--gaze-left-left", `${(gaze === "left" ? leftPoseLeftEyeX : gaze === "right" ? rightPoseLeftEyeX : 3).toFixed(2)}px`);
  orb.style.setProperty("--gaze-right-left", `${(gaze === "left" ? leftPoseRightEyeX : gaze === "right" ? rightPoseRightEyeX : 23).toFixed(2)}px`);
  orb.style.setProperty("--gaze-near-width", `${nearWidth}px`);
  orb.style.setProperty("--gaze-far-width", `${farWidth}px`);

变量的含义：
- --gaze-left-left：左眼框的 left 坐标。
- --gaze-right-left：右眼框的 left 坐标。
- --gaze-near-width：靠近注视方向一侧眼框的宽度。
- --gaze-far-width：远离注视方向一侧眼框的宽度。
- --gaze-strength：视线偏移强度；JS 用它计算上述坐标和宽度。
- gaze 为 left/right/center 时，JS 选择对应坐标；center 使用默认坐标 3px 和 23px。
- 右视线坐标是根据脸宽 34px 镜像计算的：34 - (另一只眼的 left + 对应宽度)。因此左右眼不是两组互不相关的硬编码位置。不要只改一侧而不重新核对镜像关系。

重要区别：JS 写入变量不代表 CSS 一定使用这些变量。必须确认被实际加载的 CSS 选择器是否用 var(--gaze-left-left)、var(--gaze-right-left)、var(--gaze-near-width)、var(--gaze-far-width)；若某条更具体的规则直接写死 left/width，则它可能覆盖或绕开变量。

眼睛和脸部最终外观：CSS 控制
----------------------------
最终像素效果通常由以下规则共同决定：
1. .limbo-pet[data-gaze="left"] ... .limbo-eye.left/right：左右视线下眼睛的 left/right/top/opacity/transform。
2. .limbo-pet[data-gaze="right"] ... .limbo-eye.left/right：右视线对应的眼睛坐标。
3. .limbo-pet[data-gaze="left"/"right"] .limbo-pet-face：脸部 rotateY、scaleX、rotateZ 角度。
4. .limbo-mouth：嘴的位置和形变。
5. .limbo-cheek.left/right：脸颊位置和透明度。
6. .limbo-pupil：瞳孔相对于眼框的位置/大小；需要同时检查眼框与瞳孔规则，不能只改眼框后假设瞳孔自然正确。
7. 宠宝主体的尺寸、脸部容器宽度、transform-origin、overflow、position 等基础规则也会影响视觉位置。

为什么有两个 CSS，以及为什么现在不合并
--------------------------------------
- pet.css 与 limbo.css 都含有相似的宠宝结构和视线规则，属于明显的职责重叠。
- 仅凭文件名和内容不能断定两者运行时都被加载；也不能断定加载顺序。必须查看 HTML/JS 入口、动态注入、import/link 引用以及实际启动页面。
- 如果两份都加载且选择器相同 specificity，通常后出现的规则胜出；如果 specificity 不同，优先级较高者可能胜出；!important、inline style、CSS custom properties 也会影响结果。
- JS 写入的 style 属性和 CSS 规则需要分开判断：inline 自定义属性会给 var() 提供值，但 CSS 选择器也可能直接写死位置。
- 贸然合并可能改变规则顺序、重复选择器的胜出结果、动画、成长状态、左右镜像或旧入口依赖。因此当前应保留两个 CSS，不删除、不合并；先完成引用关系和规则覆盖分析，再单独制定迁移方案。

--------------------------
1. 先读本文件，确认当前正确左右视线规则和脸部角度。
2. 检查 pet.js 的 setGaze()：看 data-gaze、strength 和 CSS 变量计算。
3. 搜索 pet.css 与 limbo.css 中所有 .limbo-eye、.limbo-pupil、.limbo-pet-face、[data-gaze] 规则。
4. 查明运行时到底加载哪个 CSS、是否同时加载以及顺序；查找 HTML <link>、JS import、动态插入的 stylesheet 和 @import。
5. 比较相同选择器、同属性的重复声明、specificity、!important、inline style 和 CSS 变量使用情况。
6. 每次只改一个明确负责的地方，不同时大改 JS 与两份 CSS。
7. 检查 left/right/center 三种视线、瞳孔、嘴、脸颊、脸角、成长/新生状态和移动端尺寸。
8. 运行 node --check backend/extension/pet/limbo/pet.js（仅验证 JS 语法，不代表视觉测试通过）。
9. 视觉确认通过后才更新本文件的“当前已确认正确”规则；不要用旧笔记覆盖新的已验证结果。
